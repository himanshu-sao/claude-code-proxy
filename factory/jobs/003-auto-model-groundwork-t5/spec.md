# Spec T5 - wire `emit_signal` into `create_message`

## Goal
`POST /v1/messages` appends one content-free record to `logs/auto_signal.log` per accepted request when `AUTO_SIGNAL_LOG` is on, using T3's `signal_log.emit_signal(request, headers, is_auto_alias)` and T1's `model_manager.is_auto_alias`. With the switch off nothing happens. Nothing about the response, routing, the `reason=` log line or `.last_model` changes.

## Approach (decisions, with reasons)
1. **Call site.** Inside `create_message`'s `try`, immediately AFTER T1's existing `logger.info(... reason=%s)` and BEFORE `convert_claude_to_openai`, the disconnect check, and the `if request.stream:` split. One call, above the split, so there is exactly one line on both the stream and non-stream paths. The stream generator and the error branches never call it, and the handler has no retry loop. It runs before conversion and the disconnect check, so a request that is valid but later fails (upstream error, 499, 500) is still logged once. That is wanted for a "what does Claude Code send" capture. A 422 never reaches the handler: FastAPI validates the body (and runs `validate_api_key`) before calling it, so a 422 or 401 cannot be logged. Proof: a test posts an invalid body and asserts 422, `emit_signal` spy not called and no file; the same fixture with a valid body asserts 1 call and 1 line.
2. **Inline, not an executor.** Reasons: (a) the call is a no-op unless `AUTO_SIGNAL_LOG` is on; (b) the cost is about 0.1 ms typical and 8-21 ms for the worst 2 MB bodies (T3 live review), small next to the seconds an upstream LLM call takes and next to the handler's own sync work (pydantic parse and `convert_claude_to_openai` of the same body); (c) most of that cost is CPU (hashing, `json.dumps`) under the GIL, so an executor would free only the tiny `write()`; (d) inline keeps line order deterministic (the analyzer reads per-session turn order) and tests need no waiting or flushing; (e) there is no pending write at shutdown, so no lost line and no executor-thread join. Trade-off accepted: a rollover (rename of up to 20 backups, once per 5 MB by default) blocks the loop for a few ms. Rejected alternative: `run_in_executor` would need a done-callback to retrieve exceptions, would drop a line on a hard kill, and would make order and tests non-deterministic.
3. **Never raises into the request.** `emit_signal` already swallows everything inside its own `try`. A call-site guard is still needed, because the ARGUMENTS (`http_request.headers`, `model_manager.is_auto_alias(request.model)`) are evaluated before `emit_signal` is entered, so an error there escapes its `try`, and the handler's outer `except Exception` would turn it into a 500. So add a private helper `_emit_signal_safe(request, http_request)` in `endpoints.py` that evaluates the arguments and calls `signal_log.emit_signal(...)` inside `try/except Exception`, logging `logger.debug("signal log skipped: %s", type(exc).__name__)`. That message must not contain `reason=`, and the helper must not add an INFO `reason=` line (T1 counts it exactly once). Import the module (`from src.core import signal_log`) and call `signal_log.emit_signal` through it so tests can patch it. Pass `http_request.headers` (the real Starlette `Headers`; `_header_map` handles it, first value wins).
4. **Switch.** `endpoints.py` reads no env and no `config` field. `signal_log._enabled()` reads `AUTO_SIGNAL_LOG` at call time. Do not touch `config.py` or `signal_log.py`; if either needs a change, report BLOCKED.
5. **Tests redirect to tmp_path.** `src/__init__.py` runs `load_dotenv(override=True)`, so a developer `.env` with `AUTO_SIGNAL_LOG=1` would make every existing `/v1/messages` test write to the real `logs/`. Add an AUTOUSE fixture in `tests/test_endpoints.py` that (before each test) does `monkeypatch.delenv("AUTO_SIGNAL_LOG", raising=False)`, `monkeypatch.setattr(signal_log, "_log_path", lambda: str(tmp_path / "auto_signal.log"))`, sets `_config.anthropic_api_key` to None so sentinel keys cannot hit a 401, and calls `signal_log.reset_for_tests()` before and after (the handler lives on a global logger). Tests that need the log call `monkeypatch.setenv("AUTO_SIGNAL_LOG", "1")`. This is the same pattern as T3's `log_file` fixture in `tests/test_signal_log.py`. `stub_upstream` already stubs the client and `_write_last_model`, so no network and no real `.last_model`. Reuse `_StubClient`, `_post`, `stub_upstream`. Python 3.9-safe, black and isort at line length 100.

## Acceptance criteria
1. With `AUTO_SIGNAL_LOG=1`, one accepted request writes exactly one `AUTOSIGNAL {json}` line, for non-stream and for stream (parametrized), for the alias and for a tier-map model; a request whose stub upstream raises (500) is still logged once. `auto` is true only for the alias. [TestClient]
2. A 422 request (invalid `reasoning_effort` or missing `messages`) with the log on returns 422, calls `emit_signal` zero times (spy) and creates no file; the same fixture with a valid body logs one line. [TestClient]
3. With `AUTO_SIGNAL_LOG` unset or `0`, a request returns 200, creates no file, and attaches no handler (`logging.getLogger("auto_signal").handlers == []`). [TestClient]
4. Header privacy: send `x-api-key`, `authorization`, `x-claude-code-session-id`, `anthropic-beta` (sentinel values), plus a sentinel in the user text. The record's `header_names` contains all four names, `beta` and `sid` are true and `sid_hash` equals sha256 `"sid:"+value`, first 8 hex. No sentinel header value and no sentinel text appears anywhere in the file. [TestClient, real Starlette `Headers`]
5. A failing log path leaves the response unchanged. Every case below is run twice, non-stream and stream, with `AUTO_SIGNAL_LOG=1` and `stub_upstream`, and compared with a baseline run of the same request with `AUTO_SIGNAL_LOG` unset. "Equal" means: same status code and same JSON body (non-stream, ignoring the generated `id`), or same status and same ordered list of SSE event types (stream). In each case `caplog` (DEBUG) must also show exactly one record from the `proxy` logger whose message starts with `signal log skipped` (or, in (a), no such record is required), and no captured record's message may contain `reason=` other than the single T1 INFO line. [TestClient]
   - (a) Unwritable path: `monkeypatch.setattr(signal_log, "_log_path", lambda: str(blocker / "auto_signal.log"))` where `blocker = tmp_path / "blocker"` is a regular file (so `os.makedirs` fails inside `emit_signal`). Response equals baseline; no file is created.
   - (b) Failure inside `emit_signal`: `monkeypatch.setattr(signal_log, "emit_signal", boom)` where `boom` raises `RuntimeError("x")`. This is the call-site guard catching an exception that escapes the callee. Response equals baseline; the DEBUG record is `signal log skipped: RuntimeError`.
   - (c) Failure while the call-site ARGUMENTS are evaluated, i.e. inside `_emit_signal_safe` before `emit_signal` is entered (the case the guard exists for). `http_request.headers` itself cannot be made to fail through TestClient, so the lever is `model_manager.is_auto_alias`. It is also called by `map_claude_model_to_openai` and by T1's `reason=` expression, so a blanket patch would 500 before the helper runs. Patch it with a wrapper over the real method that raises `RuntimeError("x")` only when called from the helper (`sys._getframe(1).f_code.co_name == "_emit_signal_safe"`) and otherwise delegates; also install a spy on `signal_log.emit_signal` and assert it was called zero times. Response equals baseline (status 200, same body or event types, still `reason=` exactly once from T1, `.last_model` call recorded); the DEBUG record is `signal log skipped: RuntimeError`. Without the guard this case yields a 500, so it fails if the guard is removed.
6. T1 regression: `test_auto_alias_request_log_and_last_model`, `test_tier_map_request_logs_tier_map_reason` and `test_disabled_alias_logs_tier_map` pass unchanged, with `reason=` exactly once; the same count holds with the signal log on. T1's `logger.info` call is not edited. [TestClient]
