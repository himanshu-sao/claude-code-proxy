# Spec: 005-error-contract-c (endpoints: non-stream errors and pre-first-chunk stream errors)

## Goal
`POST /v1/messages` returns every failure as a real HTTP status with the Anthropic envelope `{"type":"error","error":{"type","message"}}` and the forwarded headers. This covers upstream errors on the non-stream path and on the stream path before the first chunk, our own 429 for exhausted keys, and internal bugs. It stops using `{"detail": ...}` and never returns HTTP 200 for a failure that happens before the first upstream chunk. Slices A and B (merged at a9bc904) supply the mapping, `UpstreamError` and `get_next_client_async(*, stream=False)`. The converter and mid-stream errors belong to slice D.

## Approach (`src/api/endpoints.py` only; no change to errors.py, client.py, config.py or response_converter.py)
Helpers (import `error_envelope`, `error_type_for_status`, `UpstreamError` from `src.core.errors`):
- `_error_response(status, error_type, message, headers=None)` returns `JSONResponse(status_code=status, content=error_envelope(error_type, message), headers=headers or None)`.
- `_mapped_response(mapped)` returns `_error_response(mapped.status, mapped.error_type, mapped.message, mapped.headers)`. Forwarded headers (retry-after, x-should-retry, request-id, anthropic-ratelimit-unified-*) are already filtered and sanitised by A. Do not re-cap or re-parse them. Upstream `retry-after` stays uncapped.
- `_exhausted_response()` returns a 429 `rate_limit_error` with message `All API keys exhausted. Please wait before trying again.` and `Retry-After` set to `str(max(1, min(60, int(config.seconds_until_key_available()))))`. The clamp is repeated here. This is the only value capped at 60. An upstream 429 without `retry-after` gets no Retry-After header (we do not invent one).

`create_message` flow:
1. Keep the existing request-id, model mapping, logging, signal log, convert, early disconnect check and `_write_last_model`. Remove the inner `try/except` blocks in the stream and non-stream branches.
2. **Non-stream:** `client = await config.get_next_client_async()`. If `None`, return `_exhausted_response()`. Otherwise `await client.create_chat_completion(...)`, then return the converted dict. An upstream failure raises `UpstreamHTTPError` (a subclass of `UpstreamError`), which the handler below turns into `_mapped_response(e.mapped)`.
3. **Stream:** `client = await config.get_next_client_async(stream=True)`. If `None`, return `_exhausted_response()`. Create `gen = client.create_chat_completion_stream(...)`. Nothing runs until the first `__anext__`, so call `first = await _await_first_chunk(gen, http_request, client, request_id)`. On success return `StreamingResponse(convert_openai_streaming_to_claude_with_cancellation(_prepend(first, gen), request, logger, http_request, client, request_id), <same media type and headers as today>)`. `_prepend` is an async generator that yields `first`, then the rest of `gen`, and calls `await gen.aclose()` in a `finally`. If `gen` ends with no chunk (`StopAsyncIteration`), pass an empty async generator.
4. **`_await_first_chunk`** (module level so it can be unit-tested; constant `FIRST_CHUNK_POLL_SECONDS = 0.25`). Run `task = asyncio.ensure_future(gen.__anext__())`. Loop: `done, _ = await asyncio.wait({task}, timeout=FIRST_CHUNK_POLL_SECONDS)`. If done, return `task.result()`. That re-raises `UpstreamError` and `StopAsyncIteration` unchanged. If not done and `await http_request.is_disconnected()`, call `client.cancel_request(request_id)`, then `task.cancel()`, await it suppressing `CancelledError`, then `await gen.aclose()` and `client.active_requests.pop(request_id, None)`, then raise a module-private `_ClientGone`. Wrap the whole loop in `except BaseException` (this covers handler cancellation by the server): cancel the task if it is not done, `aclose` the generator, pop `active_requests`, and re-raise. CancelledError is never reported as a model failure (A guarantees that). `create_message` maps `_ClientGone` to `_error_response(499, "api_error", "Client disconnected")`. Nobody reads it.
5. **Hang before the first chunk:** there is no extra timer. The bound is the SDK client's `REQUEST_TIMEOUT` (`timeout=` on the httpx client, applied per phase), with `STREAM_MAX_RETRIES` retries (default 0). When it expires the SDK raises `APITimeoutError`, which A maps to `UpstreamError` with status 500 and type `api_error`. The client therefore gets a real HTTP 500 before any byte, and Claude Code retries it. No new env var and no `asyncio.wait_for`.
6. **One outer handler**, in this order (UpstreamHTTPError is also an HTTPException, so it must come first):
   - `except UpstreamError as e:` return `_mapped_response(e.mapped)`. Do not report to config here; the client already did, exactly once.
   - `except _ClientGone:` as above.
   - `except HTTPException as e:` return `_error_response(e.status_code, error_type_for_status(e.status_code), str(e.detail), e.headers)`. This covers the 499 early-disconnect and the 499 cancel from the client.
   - `except Exception:` log the traceback server-side and return `_error_response(500, "api_error", "Internal server error")`. This covers conversion bugs, a failing stub and so on. The message never includes `str(e)`.
   - `CancelledError` is not caught.
   `validate_api_key` (a dependency) and FastAPI request-validation 422s keep their current `{"detail": ...}` shape. They are outside this slice.
7. Never call sync `config.get_next_client()`. Log one line per error (request id, status, error type only; the client already logs redacted text).
