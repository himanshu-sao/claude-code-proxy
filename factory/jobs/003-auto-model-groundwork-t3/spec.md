# Spec T3 - signal log module, tests, analysis script

## Goal
Add a content-free, opt-in, append-only request "signal" log (`logs/auto_signal.log`, env `AUTO_SIGNAL_LOG`) plus an offline script that summarizes it, so real Claude Code traffic can show which effort/thinking/session fields arrive and whether a session-id hash or a first-user-message hash is the better conversation key for job 004. Nothing here changes request handling.

## Approach
Files: new `src/core/signal_log.py`, new `tests/test_signal_log.py`, new `scripts/analyze_signal_log.py` (stdlib only, Python 3.9-safe, not collected by pytest). `config.py` is untouched; the module reads `os.environ` at call time. It imports nothing from `src.core.logging` or T2. Public API: `build_signal_record(request, headers, is_auto_alias) -> dict` (pure, never raises), `emit_signal(request, headers, is_auto_alias) -> None` (no-op unless enabled; everything in try/except, failures to DEBUG on `logging.getLogger("proxy")`), `_log_path()` (project root from `__file__`, `logs/auto_signal.log`, same derivation as `logging.py:28-31`; tests monkeypatch it), `reset_for_tests()` (closes and removes handlers).

Logger: `logging.getLogger("auto_signal")`, INFO, `propagate=False`, one `RotatingFileHandler(mode="a", encoding="utf-8", delay=True, maxBytes, backupCount)` created lazily under a `threading.Lock` after an in-lock check of `logger.handlers`. `os.makedirs(dir, exist_ok=True)` first. The handler subclass overrides `handleError` to DEBUG-log instead of printing. Formatter `"%(asctime)s | %(message)s"`; the message is `AUTOSIGNAL ` plus `json.dumps(rec, sort_keys=True, separators=(",", ":"), ensure_ascii=True)` (so no newlines). Enabled = `AUTO_SIGNAL_LOG` stripped, lowercased, in `{1,true,yes,on}`. `AUTO_SIGNAL_LOG_MAX_BYTES` (default 5242880) and `AUTO_SIGNAL_LOG_BACKUP_COUNT` (default 3): non-int or <=0 falls back to the default.

Record keys (all strings capped at 64 chars, name lists capped at 50): `body_fields` (sorted `model_fields_set | model_extra` names), `header_names` (sorted lowercased names, never values; first value wins on duplicates), `model`, `auto`, `stream`, `max_tokens`, `msgs`, `last_tool_result`, `tools`, `images`, `reasoning_effort` and `oc_effort` (value if in `low|medium|high|xhigh|max`, else `"other"`, None if absent), `oc_keys`, `think_type` (`enabled|disabled|adaptive|other`), `think_budget` (int or None), `beta`, `sid`, `agent`, `parent_agent`, `req_class` (`main|subagent|workflow|compaction|auxiliary|other`), `meta`, `meta_keys`, `est_tokens`, and the two hashes below. `est_tokens` = chars//4 over system text, message text, `json.dumps` of tool_use input, tool_result text, and `json.dumps` of tool name/description/schema; image blocks count 0 (base64 excluded); unknown blocks (thinking, redacted_thinking) are skipped.

**Hash decisions.** Algorithm: SHA-256, lowercase hex, first 8 chars (32 bits), unsalted, with a fixed domain prefix (`"sid:"` / `"msg:"`) so the two hashes of the same text differ. Unsalted so hashes stay comparable across restarts and rotated files; the security reviewer judges this and the guess risk for short prompts. `sid_hash` hashes the raw `x-claude-code-session-id` value; omitted if the header is absent.
`fm_hash` hashes the first message with `role == "user"`, using ONLY its text: a str content, or the `text` of `type=="text"` blocks. From that text, delete every `<system-reminder>...</system-reminder>` span (regex, DOTALL, non-greedy; an unclosed opening tag deletes to the end), drop tool_result/image/other blocks, join the remaining blocks with `"\n"`, collapse all whitespace runs to one space, strip, and hash the first 512 characters. This is what stops injected CLAUDE.md/date reminders from making unrelated conversations collide. `fm_hash` is omitted if there is no user message or nothing remains after stripping; `fm_stripped` (bool) records whether any reminder text was removed.

**Telling the two measurements apart (`scripts/analyze_signal_log.py`).** Both use only records that have both `sid_hash` and `fm_hash`; others are counted and reported as excluded.
- (a) Repeat rate: group by `fm_hash` and count DISTINCT `sid_hash` per group. Report groups with more than 1 session, the share of sessions whose `fm_hash` is shared, and the top 5 groups by session count (hashes only). High sharing means `fm_hash` collides across unrelated sessions (injected boilerplate, or the same opening prompt) and is unsafe as a key.
- (b) Constancy: group by `sid_hash` and count DISTINCT `fm_hash` across that session's turns, using only main-thread records (`agent == false`), because subagents share the session id but start with a different first message. Report sessions with 2 or more turns, the share with exactly 1 distinct `fm_hash`, and a distribution of distinct counts. Also report the same figure over all records, to show the subagent effect. Compaction can legitimately change the first message.
- Verdict line: `fm_hash` is usable only if (b) is near 100% and (a) is near 0%; the `sid_hash` key is judged by its presence rate.

The script takes one or more files, skips lines without `AUTOSIGNAL ` or with non-dict/invalid JSON, warns on unreadable files (stderr, continue), prints usage and exits 2 only with no arguments, and otherwise exits 0, including for empty or garbage input. Sections: field-name and header-name frequencies; effort and thinking presence for `auto` vs non-auto; `est_tokens`, `tools` and `max_tokens` stats (min/median/p90/max); tool-result share; `req_class` distribution; auxiliary/subagent share (`agent` true, or `req_class` in subagent/auxiliary); the (a)/(b) comparison.

## Acceptance criteria
1. With `AUTO_SIGNAL_LOG` unset or falsy, `emit_signal` adds no handler to `auto_signal`, creates no file or directory, and writes no line (tmp path).
2. With it on, each `emit_signal` call appends exactly one line to the file; the same line reaches neither a root-logger handler nor `proxy.log` (`propagate=False`; a capturing root handler sees 0 `auto_signal` records). Lines contain no embedded newline, even if inputs contain newlines.
3. Sentinel test: a request with unique sentinel strings in the system prompt (str and list forms), user text, an assistant tool_use input, tool name/description/schema property names and values, tool_result text, base64 image data, metadata values, an extra body field's value, an unknown `output_config.effort` value, a garbage request-class value, and header VALUES (`x-api-key`, `authorization`, `anthropic-beta`, `x-claude-code-session-id`) produces a line containing none of them. The raw session id is absent but `sid_hash == sha256("sid:"+id)[:8]`.
4. The same test asserts all listed record keys are present with correct values (counts, `last_tool_result`, `images`, `oc_keys`, enum-filtered effort, `think_type`/`think_budget`, header names lowercased and sorted, presence flags, `est_tokens` > 0 and excluding base64 length).
5. Hash tests: two requests that differ only in an injected `<system-reminder>` block (inline, or as a separate text block) get the same `fm_hash`, with `fm_stripped` true; different real text gives a different hash; the hash is computed from the first user message, not later ones; no user message, a tool_result-only first message, or an empty one omits `fm_hash`; no session header omits `sid_hash`.
6. Builder robustness: `system` as a list or None, `tools` None, str content, thinking/redacted_thinking blocks, list-valued tool_result, empty `messages`, `metadata` None, `thinking={"type":"adaptive"}` (budget None), missing or duplicate headers, and a 5 MB body all return a dict without raising. `emit_signal` with a builder that raises logs nothing and does not propagate.
7. Append and restart: `reset_for_tests()` followed by a new emit keeps the earlier lines (file not truncated). Two threads racing on the first emit leave exactly one handler and one line per call.
8. Rotation: with `AUTO_SIGNAL_LOG_MAX_BYTES` tiny and `BACKUP_COUNT=2`, many emits produce `auto_signal.log`, `.1`, `.2` and no `.3`. Invalid values (`abc`, `0`, `-5`, empty) fall back to 5242880 and 3 without raising at import or emit.
9. A missing `logs/` directory (nested tmp path) is created on first emit. An unwritable path (a regular file where the directory should be, or a read-only directory) makes `emit_signal` return normally with no exception and no stderr traceback.
10. `LOG_LEVEL=WARNING` (and a root logger at WARNING) does not suppress the signal line.
11. `scripts/analyze_signal_log.py` on an empty file, a garbage file, a nonexistent path plus a valid file, and `.log` plus `.log.1` combined exits 0 and prints each section; with no arguments it exits 2.
12. Analyzer on a synthetic log (built in the test with `emit_signal`, run through `subprocess` with `sys.executable`, tmp files only) reports: (a) a shared `fm_hash` across 3 distinct session hashes as a 3-session group; (b) a session with 4 main-thread turns and 1 subagent turn of a different first message as constant in the main-thread figure and non-constant in the all-records figure. This proves the two measurements are separate.
13. Tests never touch the real `logs/` (all use a monkeypatched `_log_path` under `tmp_path` and env via `monkeypatch`); `uv run pytest tests/test_signal_log.py` passes offline, and the offline suite `uv run pytest tests/test_effort_mapper.py tests/test_endpoints.py tests/test_context_manager.py tests/test_signal_log.py` passes.
14. `uv run black --check src/ && uv run isort --check src/` pass (line-length 100); `git check-ignore logs/auto_signal.log` reports it ignored. Docs and `.env.example` entries for the two new env vars belong to the docs task, not T3.
